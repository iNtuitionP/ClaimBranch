# Design: concise outcome

## Purpose

Describe the problem, users or systems affected, and why a design document is
needed.

## Context and current state

Orient a repository newcomer and link canonical product and architecture docs.

## Goals and non-goals

State boundaries and observable qualities.

## Decision drivers

List constraints, risks, and quality scenarios that differentiate options.

## Options considered

Compare credible alternatives and the status quo.

## Proposed design

Describe responsibilities, data and control flow, interfaces, and failure
behavior without presenting the proposal as implemented truth.

## Security privacy and human-control boundaries

State trust boundaries, data disclosure, permissions, and irreversible actions.

## Migration and rollback

Explain compatibility, rollout, recovery, and cleanup.

## Validation

Define tests, measurements, and end-to-end acceptance.

## Open questions

List only questions that can change the decision.

## Outcome

When review ends, record the disposition and link any resulting ADR, current
architecture update, and ExecPlan.
